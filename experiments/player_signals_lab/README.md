# Disposable player signals lab

This directory owns every experiment, configuration, test, cache, and result it creates.
It imports Patron's verified gold reader, preseason panel, reference baseline, and fixed
NextGen challengers as read-only dependencies. It has no model registration, publishing,
API, CLI, frontend, or package-build integration. **Delete this directory to remove the lab.**

The starting hypotheses come from the
[NFL literature review](../../docs/nfl_player_research_literature_review_2026-09-23.md).
The scope includes retrospective **preseason season-level** forecasting and a separate
historical weekly QB role experiment. Existing rankings and research work remain separate.

Start with the [additional experiments and recommendations](followup_readout.md) and the
[interactive follow-up report](runs/review_003/index.html), including population calibration.
The [research-path ledger](research_queue.md) records executed tests and remaining data limits.
For the first experiment round, see [initial findings](initial_readout.md), then open
the completed [searchable comparison report](runs/literature_002/index.html) or
[full generated report](runs/literature_002/report.md). These links refer to saved local
results, which are intentionally ignored by Git. The commands below regenerate results
in new, automatically named directories.

From the repository root, using the existing environment:

```sh
# Validate the isolated methods and leakage/write boundaries.
PYTHONDONTWRITEBYTECODE=1 .venv/bin/pytest -p no:cacheprovider \
  --basetemp=experiments/player_signals_lab/.test-tmp \
  experiments/player_signals_lab/tests

# Small plumbing check (not an efficacy result; no interval warmup).
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python experiments/player_signals_lab/run.py \
  --smoke

# All eleven tasks, 2007–2025 expanding-window folds.
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python experiments/player_signals_lab/run.py

# Follow-up stages; each creates a separate guarded run directory.
# These four stages depend on the verified literature_002 run.
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python experiments/player_signals_lab/run_followup.py \
  --stage calibration
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python experiments/player_signals_lab/run_followup.py \
  --stage signals
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python experiments/player_signals_lab/run_followup.py \
  --stage structure
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python experiments/player_signals_lab/run_followup.py \
  --stage distributions

# Audit/closure reuses the exact saved calibration_001/signals_001/structure_001 results.
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python experiments/player_signals_lab/run_followup.py \
  --stage audit

# Combined report from those completed trials and audit_002; use a new run ID.
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python experiments/player_signals_lab/build_followup_report.py \
  --run-id my_followup_report --audit-run audit_002
```

Open `runs/<run-id>/index.html` directly in a browser for searchable comparisons, or
read `runs/<run-id>/report.md`. Machine-readable predictions, calibration diagnostics,
annual losses, parameters, cohort coverage and provenance live beside them. A run is
usable only when its manifest says `status: complete` and `protected_inputs_unchanged: true`.

Follow-up stage outputs are Parquet/JSON; the combined HTML is generated by
`build_followup_report.py`. Their saved-run dependencies are explicit, not a moving `latest`
pointer. To recreate after removing all runs, first run the original full experiment with
`--run-id literature_002`, then the four follow-up stages with IDs `calibration_001`,
`signals_001`, `structure_001`, and `distributions_001`, then audit with `--run-id audit_002`.
Existing IDs cannot be overwritten. Source and external data pins must still match; changing
the dependency graph requires an explicit new local protocol/configuration.

Run IDs are create-only. Choose a new ID for each trial; failed trials also retain their
directory and manifest. There is deliberately no `latest` pointer or promotion command.
For a new hypothesis, copy `config.json` **within this directory**, change it, and pass
`--config experiments/player_signals_lab/<your-config>.json`. Freeze the hypothesis and
its control before reading its results. Changing the booster config changes lab recipes;
the imported NextGen reference/boost recipes retain their source definitions.

| Experiment | Question | Matched control |
| --- | --- | --- |
| `raw_rates` | Do explicit efficiency rates/exposures add to existing history? | Imported NextGen boost |
| `pooled_rates` | Does exposure-aware pooling improve on the same raw rate block? | `raw_rates` |
| `market_pooled` | Does pooling help after cutoff-safe ECR? | `market_control` |
| `participation` / `market_participation` | Do measured passing-play participation and target earning add information? | Raw rates / market control |
| `role_direct` / `market_role_direct` | Does prior duration of meaningful QB passing usage add information? | Raw rates / market control |
| `role_mixture` / `market_role_mixture` | Do conditional workload experts improve on direct prediction with identical inputs? | Corresponding role direct model |
| Absolute / scaled intervals | Is forecast uncertainty calibrated, and is the width useful? | Same point model and identical evaluation rows |

All mean models use squared-error fitting. MSE is primary and MAE secondary; earlier
OOF residual median shifts get their own median-oriented MAE diagnostic. No recipe is
selected automatically and no fitted production model is saved. See [protocol.md](protocol.md)
for temporal and statistical contracts and [research_queue.md](research_queue.md) for the
complete mapping of review recommendations, including prerequisites for unimplemented tracks.

Isolation is deliberately redundant:

- The gold version **and its manifest hash** are pinned in the config and validated by the
  existing release reader. Incomplete outcomes never enter the experiment.
- The runner disables bytecode writes and restricts Python writes to its newly created run
  directory. Links, subprocesses and network calls are blocked after startup.
- Source/config snapshots, dependency versions and SHA-256 hashes are recorded. Loaded gold
  tables, imported source modules, configuration and lab code are rehashed after the run.
  Imported library code is also pinned in the config. Changes to these dependencies invalidate
  the run. The current catalog, other application source and research manifests/registries
  are monitored separately: concurrent changes are logged, but cannot alter the pinned inputs.
  This allows unrelated work elsewhere in the shared workspace to continue.
- Native extensions are not fully covered by Python audit hooks. Our native Parquet writer
  receives only a lab-owned path; input hashes verify the protected files. This is an accident
  barrier for trusted experiments, not a hostile-code or whole-filesystem security sandbox.
- Tests use a lab-local temporary directory and disable pytest's shared cache. Result files
  are locally ignored by the lab's own `.gitignore`; nothing changes the root ignore rules.

Cleanup, after the runner has exited:

```sh
# Remove only results and test temporary files, retaining the lab.
rm -rf experiments/player_signals_lab/runs experiments/player_signals_lab/.test-tmp

# Or remove the entire lab, including its code, documentation and results.
rm -rf experiments/player_signals_lab
```

No other cleanup, migration, registry edit, or model retraining is required. References go
from the lab to the library; the library does not import the lab.
